# Архитектура приложения

**Источник:** лабораторная работа № 3. Связи и интерфейсы модулей — в соседнем файле [module-interfaces.md](module-interfaces.md). Обоснование выбора технологий — [technologies.md](technologies.md).

**Тип: локальное веб-приложение с клиент-серверной архитектурой.**

**Почему такой выбор:**
- **Независимость:** данные пользователя и вся работа с колодами хранятся локально в SQLite. Сервер .NET работает на `localhost` — не требуется развёртывание удалённого сервера и платная инфраструктура.
- **Чистый веб без оболочки:** не нужны Electron/WebView2 — меньше размер сборки, число зависимостей и потребление ОЗУ; приложение запускается в любом современном браузере.
- **Разделение ответственности:** тяжёлые операции (парсинг PDF/DOCX, OCR на C#-библиотеках, работа с SQLite) вынесены на Backend (.NET); интерфейс (JS) остаётся лёгким и отзывчивым.
- **Сроки и опыт команды:** .NET для бэкенда и веб-стек для фронтенда позволяют разделить задачи между участниками команды.

## 1. Модуль пользовательского интерфейса (UI)

- **Где:** клиентская часть (JavaScript / HTML5 / CSS3).
- **Назначение:** взаимодействие с пользователем, отображение данных, сбор параметров.
- **Основные функции:**
  - отрисовка экранов: «Конструктор промптов», «Просмотр колод/карточек», «Редактор карточки», «Печать»;
  - загрузка файлов и изображений drag-and-drop;
  - формирование фильтров, поиска и сортировки по тегам/метаданным;
  - генерация печатных версий карточек.
- **Границы:** не занимается парсингом файлов, валидацией JSON и прямой работой с БД. Отправляет HTTP/JSON-запросы на локальный бэкенд.

## 2. Модуль обработки и парсинга документов (Document Parsing)

- **Где:** серверная часть (.NET / C#).
- **Назначение:** извлечение сырого текста из загруженных файлов и фотографий.
- **Основные функции:**
  - парсинг текстовых файлов форматов `.pdf`, `.docx`, `.doc`, `.txt` (C#-библиотеки `PdfPig`, `DocumentFormat.OpenXml`);
  - модуль OCR: очистка изображений (`.jpg`, `.png`), распознавание и извлечение печатного/рукописного текста с фото документов;
  - предобработка текста: нормализация, удаление мусорных символов, разбиение на чанки при превышении лимита размера.
- **Границы:** отвечает только за превращение разнородных файлов в единую текстовую строку (`string`).

## 3. Модуль взаимодействия с ИИ (AI & Prompt Management)

- **Где:** серверная часть (.NET / C#).
- **Назначение:** формирование системного промпта, отправка запросов к LLM API и контроль качества ответа.
- **Основные функции:**
  - сборка финального промпта: объединение извлечённого текста и пользовательских параметров (детализация, стиль, формат) в системный шаблон;
  - выполнение HTTPS-запросов к внешней системе (OpenAI / DeepSeek API) с поддержкой таймаута (30 сек);
  - **валидация ответа ИИ:** проверка JSON-ответа на соответствие строгой схеме.
- **Границы:** отвечает за логику генерации. При сетевой ошибке или сбое валидации формирует структурированный код ошибки для UI.

## 4. Модуль управления данными и колодами (Data Access)

- **Где:** серверная часть (.NET / C#).
- **Назначение:** бизнес-логика работы с колодами, карточками и метаданными.
- **Основные функции:**
  - CRUD-операции с колодами (создание, переименование, теги, удаление);
  - CRUD-операции с карточками (сохранение сгенерированной карточки, ручное редактирование конспекта/заданий, удаление);
  - логика экспорта и импорта колод в файл обмена (JSON-пакет);
  - поисковый движок: фильтрация и выборка карточек по метаданным/тегам/дате.
- **Границы:** управляет состоянием объектов приложения. Не обращается к файлу БД напрямую — использует DAL (Data Access Layer).

## 5. Модуль локального хранения (Database)

- **Где:** серверная часть (.NET / C# + SQLite).
- **Назначение:** надёжное офлайн-хранение структуры данных.
- **Основные функции:**
  - инициализация и создание таблиц SQLite (`Decks`, `Cards`, `Tags`, `History`);
  - выполнение SQL-запросов (ORM / Entity Framework Core / Dapper).
- **Границы:** чтение и запись файлов `.db` на диске; не содержит бизнес-правил редактирования.

## Внешняя система (External Dependence)

- **LLM Provider API:** внешний сервис ИИ (за границами системы, доступ по сети).
