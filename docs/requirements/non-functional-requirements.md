# Нефункциональные требования

**Источник:** лабораторная работа № 2 (экспорт Anytype от 03.11.2026). Фундамент: [functional-requirements.md](functional-requirements.md).

## Условия эксплуатации

- Устройство запуска ПО:
  - клиент — обычный современный браузер (Chrome, Edge, Firefox актуальных версий); отдельная оболочка Electron/WebView2 не требуется;
  - серверная часть — ОС Linux / Windows 10–11;
  - стабильное подключение к интернету (для внешнего API ИИ).

## Надёжность

- Поддержка локальной СУБД SQLite; автоматическое резервное копирование пользовательской базы данных в локальный файл-дамп при закрытии приложения или изменении колод.
- Вызов ошибок не должен нарушать работу системы.

## Производительность

- Режим работы: однопользовательское локальное приложение.
- Время отклика системы:
  - операции интерфейса (поиск, фильтрация, открытие карточки, просмотр колоды) — **не более 1 секунды**;
  - извлечение текста/OCR из файла объёмом до 20 страниц — **не более 3 секунд**;
  - максимальное время ожидания ответа от ИИ — **30 секунд**; во время генерации UI отображает индикатор загрузки.

## Технологические требования

- Требования к I/O между клиентом и ИИ:
  - входные данные для обработки ИИ — в JSON-формате;
  - выходные данные после обработки ИИ — в JSON-формате.
- Требования к импорту и экспорту данных:
  - входные данные для обработки парсером — форматы `txt`, `doc`, `pdf`;
  - выходные данные для экспорта — формат `pdf`.
- Хранение данных: СУБД SQLite для локального хранения данных.
- Клиентская часть:
  - UI — на веб-технологиях (HTML5 + CSS3);
  - ЯП клиентской логики — JavaScript.
- Серверная часть:
  - серверная логика — на технологии .NET;
  - ЯП серверной логики — C#;
  - интеграция с API ИИ и OCR-библиотеками.

## Требования к UI

- UI соответствует современным стандартам вёрстки пользовательских интерфейсов.
