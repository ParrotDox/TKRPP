# MVP — минимальные функции для демонстрации

**Источник:** лабораторная работа № 2.

| ID. Название процесса | Приоритет | Объяснение |
|---|---|---|
| **US-0N**. Просмотр сущности | **Must** | Базовая навигация, без неё невозможно взаимодействие с приложением. |
| **US-03-01**. Генерация карточки | **Must** | Автоматическая генерация конспекта ИИ — ключевой шаг демонстрации MVP. |
| **US-01-01**. Создание/удаление колоды | **Must** | Без колод некуда структурировать карточки по темам. |
| **US-01-03**. Добавление/удаление карточки из колоды | **Must** | Базовая механика наполнения колоды контентом. |
| **US-02-03**. Уничтожение карточки | **Must** | Необходима для очистки хранилища от ошибочных данных. |
| **US-03-02**. Загрузка файлов материалов | **Must** | Ядро продукта: без исходных данных ИИ не может работать. |
| **US-03-05**. Сохранение сгенерированной карточки | **Must** | Завершающий шаг сценария работы с карточкой. |

## Законченный сценарий демонстрации MVP

1. Студент открывает приложение и просматривает главный экран (US-0N).
2. Создаёт новую колоду с названием «Название» (US-01-01).
3. Загружает файл учебника в формате `.pdf` (US-03-02).
4. Подтверждает сохранение сгенерированной системой карточки в колоду «Название» (US-03-01, US-03-05).
5. Открывает колоду «Название» и проверяет, что карточка успешно добавилась и отображается (US-01-03, US-0N).
6. Открывает общее хранилище карточек и удостоверяется в наличии созданной карточки (US-0N).
7. Студент удаляет неудачную карточку или всю колоду, проверяя работу механизма очистки (US-02-03, US-01-01).

## Разбивка MVP по спринтам (см. план)

- **Спринт 1** — минимальный UI и парсинг: US-03-02 (+ каркас US-0N, элементы интерфейса US-03-03) — пользователь загружает файл и видит извлечённый текст.
- **Спринт 2** — генерация, хранение и колоды: US-03-01, US-03-03 (логика), US-03-05, US-0N, US-01-01, US-01-03, US-02-03 — после него сценарий демонстрации MVP проходится целиком.
