# Анализ существующего алгоритма действий
#### Глоссарий страницы
- Контрольная точка - место в учебных материалах, на которых остановился студент в последний раз
#### Анализ алгоритма изучения материалов
В текущих условиях обучения студентам требуется открывать огромное количество обучающих материалов в word, pdf форматах, изучать их и выписывать ключевые моменты. 
Такой способ просмотра материала хоть и удобен, но имеет следующие недостатки:
- Небольшие, но огромные затраты. Открытие файлов и поиск контрольной точки в материалах после каждой перезагрузки компьютера ведет к хоть и небольшой, но немаловажной задержке. Одно открытие и поиск информации может занять около 5-10 секунд, но суммарно, сложив все открытия, полученные значения потраченного времени могут увеличиться
- Научный стиль. Огромное количество научного текста сложно запоминается студентами. Для понимания сути учебных текстов, требуется обрабатывать материал через призму "студента"
- Недостаток времени. Создание конспектов зачастую ведется традиционным способом - написанием в тетради или современным - написанием цифрового материала. Оба способа отнимают жизненно важное для студента время, что направляют его фокус не на изучение материала, а на обработку и лаконичную передачу материала
Таким образом, основными недостатками преобладающего среди студентов подхода конспектирования и практики материала являются недостаток времени и научный стиль, скрывающий основную суть теории сложными синонимами слов.


# I/O данные программы
#### Входные данные
- Фото документа:
	- OCR (технология)
- Файлы с расширением:
	- word
	- txt
	- pdf
- Команды пользователя на формирование корректного промпта:
	- TextInput: Указание пользователем требуемых терминов и тем для формирования конспекта/задания
	- Указание пользователем стиля, тона написания текста конспектов/заданий
(сохранить исходный, краткий, "на пальцах")
	- Проверка/валидация (строгая/простая)
	- Тип выдаваемого результата (конспект, задание, смешанный)
- Общие команды:
	- Команда выбора окна создания промпта для ИИ
	- Команда отправки промпта ИИ
	- Команда сохранения результата промпта в локальном хранилище
	- Команда просмотра сохраненных результатов
	- Команда прикрепления тегов для сохраненных результатов ИИ (для сортировки по темам)
	- Команда печати полученных результатов на принтере
#### Выходные данные
- Результат поданного на вход промпта от ИИ (данные о карточке)
	- Текстовые конспекты
	- Текстовые карточки с заданиями
	- Ключевые термины
	- Тема
	- Дата и время генераци
- Рекомендации по сохранению результата, повтора генерации или удалению полученного результата ИИ
- Рекомендация по печати материалов на принтере

	- Просмотр колоды:
		- Поиск карточек по метаданным;
		- Сортировка учебных карточек
	- Удаление учебной карточки (в колоде);
	- Уничтожение колоды
	- Экспорт/импорт колоды файловом формате
- Управление готовой учебной карточкой:
	- Редактирование учебных карточек:
		- Теги карточки;
		- Название карточки;
		- Учебный материал карточки;
		- Summary карточки;
		- Ключевые слова;
	- Уничтожение карточки;
	- Печать карточки при помощи принтера;
	- Экспорт материалов карточки.
#### Функции системы (автоматические)
- Формировать карточку по запросу на базе ИИ:
	- Конспект;
	- Метаданные;
- Выполнять проверку ответа ИИ:
	- На заполнение требуемых данных ответа;
	- На соблюдение контекста;
	- На последовательность;

# Нефункциональные требования
#### Условия эксплуатации
- Устройство запуска ПО
	- Поддержка веб-движка Chromium
	- ОС Linux/Windows 10-11
	- Стабильное подключение к интернету
#### Надежность
- Целостность данных в системе обеспечивается засчет автоматического резервного копирования коллекции в отдельный файл
- Вызов ошибок не должен нарушать работу системы
#### Производительность
- Один экземпляр системы должен обслуживать одного пользователя
- Время отклика системы не должно превышать 10с при запросах с использованием ИИ, в остальных случаях - не более 2с
#### Технологические требования
- Требования к I/O между клиентом и ИИ
	- Входные данные для обработки ИИ должны быть представлены в JSON формате
	- Выходные данные после обработки ИИ должны быть представлены в JSON формате
- Требования к импорту и экспорту данных
	- Входные данные для обработки парсером представлены в txt, doc, pdf формате
	- Выходные данные для экспорта представлены в pdf формате
- Хранение данных
	- СУБД SQLite для локального хранения данных
- Клиентская часть
	- UI должен быть написан на веб-технологиях
	- ЯП написания клиентской логики - JavaSript
- Серверная часть
	- Серверная логика должна быть написана с применением технологии .NET
	- ЯП написания серверной логики - C#
#### Требования к UI
- UI соответствует современным стандартам верстки пользовательских интерфейсов
# Архитектура проекта
## **Тип: Локальное Desktop-приложение с клиент-серверной архитектурой**   
   
**Почему такой выбор?:**   
- **Независимость:** Данные пользователя и вся работа с колодами хранятся локально в SQLite. Сервер .NET работает на `localhost`, поэтому приложение не требует развертывания удаленного сервера и платной инфраструктуры.   
- **Разделение ответственности:** Тяжёлые операции (парсинг сложных PDF/DOCX, обработка OCR через C#-библиотеки, работа с SQLite) вынесены на Backend (.NET). Интерфейс (JS) остается легким, быстрым и отзывчивым.   
- **Сроки и опыт команды:** Использование .NET для бэкенда и веб-стека для фронтенда позволяет разделить задачи между 4 участниками команды.   
   
   
### 1. Модуль пользовательского интерфейса (UI)   
- **Где находится:** Клиентская часть (JavaScript / HTML5 / CSS3).   
- **Назначение:** Взаимодействие с пользователем, отображение данных и сбор параметров.   
- **Основные функции:**   
    - Отрисовка экранов: «Конструктор промптов», «Просмотр колод/карточек», «Редактор карточки», «Печать».   
    - Загрузка файлов и изображений drag-and-drop.   
    - Формирование пользовательских фильтров, поиска и сортировки по тегам/метаданным.   
    - Генерация специальных печатных версий.   
- **Границы ответственности:** Не занимается парсингом файлов, валидацией JSON или прямо работой с БД. Отправляет HTTP/JSON-запросы на локальный бэкенд.   
   
### 2. Модуль обработки и парсинга документов (Document Parsing)   
- **Где находится:** Серверная часть (.NET / C#).   
- **Назначение:** Извлечение сырого текста из загруженных файлов и фотографий.   
- **Основные функции:**   
    - Парсинг текстовых файлов форматов `.pdf`, `.docx`, `.doc`, `.txt` (использование C#-библиотек `PdfPig`, `DocumentFormat.OpenXml`).   
    - Модуль OCR: очистка изображений ( `.jpg`, `.png`), распознавание символов и извлечение печатного/рукописного текста с фото документов.   
    - Предобработка текста: нормализация, удаление мусорных символов, разбиение на чанки при превышении лимита размера.   
- **Границы ответственности:** Отвечает ТОЛЬКО за превращение разнородных файлов в единую текстовую строку ( `string`).   
   
### 3. Модуль взаимодействия с ИИ (AI & Prompt Management)   
- **Где находится:** Серверная часть (.NET / C#).   
- **Назначение:** Формирование системного промпта, отправка запросов в LLM API и контроль качества ответа.   
- **Основные функции:**   
    - Сборка финального промпта: объединение извлеченного текста и параметров пользователя (детализация, стиль, формат) в системный шаблон.   
    - Выполнение HTTPS-запросов к внешней системе (OpenAI / DeepSeek API) с поддержкой таймаута (30 сек).   
    - **Валидация ответа ИИ:** проверка полученного JSON-ответа на соответствие строгой схеме.   
- **Границы ответственности:** Отвечает за логику генерации. При сетевой ошибке или сбое валидации формирует структурированный код ошибки для UI.   
   
### 4. Модуль управления данными и колодами (Data Access)   
- **Где находится:** Серверная часть (.NET / C#).   
- **Назначение:** Реализация бизнес-логики работы с колодами, карточками и метаданными.   
- **Основные функции:**   
    - CRUD-операции с колодами (создание, переименование, назначение тегов, удаление).   
    - CRUD-операции с карточками (сохранение сгенерированной карточки, ручное редактирование конспекта/заданий, удаление).   
    - Логика экспорта и импорта колод в единый файл обмена (JSON-пакет).   
    - Поисковый движок: фильтрация и выборка карточек из базы по метаданным/тегам/дате.   
- **Границы ответственности:** Управляет состоянием объектов приложения. Не обращается к файлу БД напрямую, а использует DAL (Data Access Layer).   
   
### 5. Модуль локального хранения (Database)   
- **Где находится:** Серверная часть (.NET / C# + SQLite).   
- **Назначение:** Надежное офлайн-хранение структуры данных системы.   
- **Основные функции:**   
    - Инициализация и создание таблиц локальной базы данных SQLite ( `Decks`, `Cards`, `Tags`, `History`).   
    - Выполнение SQL-запросов (через ORM / Entity Framework Core / Dapper).   
    - Создание локальных бэкапов (резервных дампов БД) в системный каталог приложения при закрытии/сохранении.   
- **Границы ответственности:** Чтение и запись в файлы `.db` на диске. Не содержит бизнес-правил редактирования.   
   
### Внешняя система (External Dependence):   
- **LLM Provider API:** Внешний сервис ИИ (находится за границами нашей системы, доступен по сети).
