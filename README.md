# Анализ существующего алгоритма действий
#### Глоссарий страницы
- Контрольная точка - место в учебных материалах, на которых остановился студент в последний раз
#### Анализ алгоритма изучения материалов
В текущих условиях обучения студентам требуется открывать огромное количество обучающих материалов в word, pdf форматах, изучать их и выписывать ключевые моменты. 
Такой способ просмотра материала хоть и удобен, но имеет следующие недостатки:
- Небольшие, но огромные затраты. Открытие файлов и поиск контрольной точки в материалах после каждой перезагрузки компьютера ведет к хоть и небольшой, но немаловажной задержке. Одно открытие и поиск информации может занять около 5-10 секунд, но суммарно, сложив все открытия, полученные значения потраченного времени могут увеличиться
- Научный стиль. Огромное количество научного текста сложно запоминается студентами. Для понимания сути учебных текстов, требуется обрабатывать материал через призму "студента"
- Недостаток времени. Создание конспектов зачастую ведется традиционным способом - написанием в тетради или современным - написанием цифрового материала. Оба способа отнимают жизненно важное для студента время, что направляют его фокус не на изучение материала, а на обработку и лаконичную передачу материала
Таким образом, основными недостатками преобладающего среди студентов подхода конспектирования и практики материала являются недостаток времени и научный стиль, скрывающий основную суть теории сложными синонимами слов.


# I/O данные программы
#### Входные данные
- Фото документа:
	- OCR (технология)
- Файлы с расширением:
	- word
	- txt
	- pdf
- Команды пользователя на формирование корректного промпта:
	- TextInput: Указание пользователем требуемых терминов и тем для формирования конспекта/задания
	- Указание пользователем стиля, тона написания текста конспектов/заданий
(сохранить исходный, краткий, "на пальцах")
	- Проверка/валидация (строгая/простая)
	- Тип выдаваемого результата (конспект, задание, смешанный)
- Общие команды:
	- Команда выбора окна создания промпта для ИИ
	- Команда отправки промпта ИИ
	- Команда сохранения результата промпта в локальном хранилище
	- Команда просмотра сохраненных результатов
	- Команда прикрепления тегов для сохраненных результатов ИИ (для сортировки по темам)
	- Команда печати полученных результатов на принтере
#### Выходные данные
- Результат поданного на вход промпта от ИИ (данные о карточке)
	- Текстовые конспекты
	- Текстовые карточки с заданиями
	- Ключевые термины
	- Тема
	- Дата и время генераци
- Рекомендации по сохранению результата, повтора генерации или удалению полученного результата ИИ
- Рекомендация по печати материалов на принтере


# Функциональные требования
#### Функции пользователя
- Управление созданием карточки:
	- Загрузка учебных материалов для конспектирования;
	- Настройка промпта для ИИ:
		- Уровень детализации (кратко, подробно);
		- Стиль написания (разговорный, официальный);
		- Формат вывода (конспект, вопрос-ответ);
	- Генерация материалов карточки на базе ИИ;
	- Сохранение учебной карточки (после генерации);
- Управление колодой:
	- Создание колоды;
	- Редактирование колоды:
		- Название колоды;
		- Теги колоды;
	- Просмотр колоды:
		- Поиск карточек по методанным;
		- Сортировка учебных карточек
	- Удаление учебной карточки (в колоде);
	- Уничтожение колоды
	- Экспорт/импорт колоды файловом формате
- Управление готовой учебной карточкой:
	- Редактирование учебных карточек:
		- Теги карточки;
		- Название карточки;
		- Учебный материал карточки;
		- Summary карточки;
		- Ключевые слова;
	- Уничтожение карточки;
	- Печать карточки при помощи принтера;
	- Экспорт материалов карточки.
#### Функции системы (автоматические)
- Формировать карточку по запросу на базе ИИ:
	- Конспект;
	- Метаданные;
- Выполнять проверку ответа ИИ:
	- На заполнение требуемых данных ответа;
	- На соблюдение контекста;
	- На последовательность;

# Нефункциональные требования
#### Условия эксплуатации
- Устройство запуска ПО
	- Поддержка веб-движка Chromium
	- ОС Linux/Windows 10-11
	- Стабильное подключение к интернету
#### Надежность
- Целостность данных в системе обеспечивается засчет автоматического резервного копирования коллекции в отдельный файл
- Вызов ошибок не должен нарушать работу системы
#### Производительность
- Один экземпляр системы должен обслуживать одного пользователя
- Время отклика системы не должно превышать 10с при запросах с использованием ИИ, в остальных случаях - не более 2с
#### Технологические требования
- Требования к I/O между клиентом и ИИ
	- Входные данные для обработки ИИ должны быть представлены в JSON формате
	- Выходные данные после обработки ИИ должны быть представлены в JSON формате
- Требования к импорту и экспорту данных
	- Входные данные для обработки парсером представлены в txt, doc, pdf формате
	- Выходные данные для экспорта представлены в pdf формате
- Хранение данных
	- СУБД SQLite для локального хранения данных
- Клиентская часть
	- UI должен быть написан на веб-технологиях
	- ЯП написания клиентской логики - JavaSript
- Серверная часть
	- Серверная логика должна быть написана с применением технологии .NET
	- ЯП написания серверной логики - C#
#### Требования к UI
- UI соответствует современным стандартам верстки пользовательских интерфейсов
